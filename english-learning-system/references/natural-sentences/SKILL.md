# Natural Sentences Daily

Build a selective library of natural, reusable sentences for independent use. Favor everyday, professional, technical, IELTS and personally relevant patterns over volume or unnecessary sophistication. Keep this workflow separate from other Memos, spaced-review tasks and quizzes; invoking one does not authorize another.

## 1. Source and access

Discover and verify the learner's dedicated Natural Sentences page, its live rules and its actual Sentence Library database and schema, including relevant views. Reuse existing verified private settings or exact-title search; check parentage, all rules and nested content, and do not use similarly named dummy databases. Live rules and later direct user instructions take precedence. Keep personal page IDs, records, credentials and user-specific schedules outside this shareable skill.

The dedicated conversation or deliberately maintained input section is the source of eligible original entries; the Notion Sentence Library is the destination and evidence of what was saved, not a substitute for missing conversation history. A Notion page's content is not proof that a ChatGPT Web conversation is accessible. Determine the actual accessible, authorized source and its dates and coverage for each run. Use the active dedicated conversation when available, an explicitly provided export, or an authorized dedicated input section. Never invent or infer messages from database gaps, search snippets or edit dates. If earlier source messages or the last successful checkpoint cannot be accessed, reconcile the portion actually available, report the specific missing window and do not claim full coverage or a complete no-op. Ask for an accessible source or export only when required for the missing work.

## 2. Select and reconcile

For an explicitly requested or already authorized daily run, determine the local date and timezone from verified private settings (the user's current workflow specifies Asia/Shanghai). Process once per run; a skill does not itself create, enable, disable or verify a scheduler. Preserve any existing schedule unless explicitly asked to manage it. Reconcile eligible unsaved entries since the last verified successful run when the original source and checkpoint are accessible; otherwise state the recovery boundary. A checkpoint may advance only across source material whose entries and authorized writes have been fully reconciled and verified. Preserve a verified original study date for backfills; never change it to the processing date.

By default select user-authored sentences deliberately entered in the dedicated source, ignoring configuration and discussion. Never automatically harvest speaking, writing, vocabulary, grammar or daily Memo sessions. An explicit request to save a particular selected or quoted sentence, including an assistant-written or corrected version, authorizes that item even outside the dedicated source; record the actual source and authorship. Merely discussing or asking about a sentence does not authorize saving it.

Paginate the entire accessible library and check both exact and near duplicates by meaningful shared pattern, not just wording. Verify existing matches and their content before deciding; a title search alone is not proof of full coverage. If a candidate teaches an existing pattern, skip creation and identify the representative sentence; add a key phrase only when requested or clearly implied and preserve user edits. Prefer the stronger representative without deleting or replacing existing entries absent explicit authorization. Stop affected creation and report a gap if library enumeration, source identity or duplicate coverage is incomplete.

Cap new entries at ten per original learning date, including backfills and existing additions for that date. Check counts first; if date or complete count is unknown, do not assume capacity. An existing match is not a new entry. If more than ten are eligible, prioritize reusable collocations, everyday usefulness, recurring personal needs, IELTS relevance and distinct structures. Do not fill the quota artificially; report remaining candidates.

## 3. Naturalize and save

For selected entries, preserve intent and original wording; correct grammar and spelling and improve collocations only where useful. Do not rewrite already natural sentences unnecessarily or change qualified factual claims. Show a concise correction and key phrases; label editorial examples and corrected versions rather than calling them independent learner use.

Using current schema and options, create the full corrected sentence, one appropriate native emoji icon, initial New status, exactly one category, relevant existing tags, key phrase(s), why it matters, original learning date, source and dated addition log; initialize review count to zero and leave last-reviewed blank. Preserve original wording in an appropriate source or learning note, without overwriting learner content. An illustrative personal example may use verified context; label it as generated and do not invent personal history. Do not create new fields, tags or categories without permission. Preserve existing row fields, notes, histories and status.

## 4. Practice and review

Only a meaningful, deliberate review that actually occurred counts: capture its date, actual attempt, feedback and context; update Last Reviewed, increment Review Count once per distinct review event and append a dated Progress Log, with idempotent event identification to prevent repeat increments on retry. Viewing, reading or explanation alone is not a review. Differentiate prompted practice, generated examples and independent use.

When the learner authorizes progress updates, apply actual evidence and current rules: New to Reviewing after meaningful review; Reviewing to Active after correct use with little prompting; Active to Mastered only after documented independent, natural, correct use on at least three separate dates. Do not automatically promote based on a count, a quotation, a single attempt or mere recognition. Respect learner-owned status and preserve prior notes and outcomes. Reconcile historically claimed backfills and review updates against actual existing records and original evidence before changing anything; never trust a copied handoff alone as proof of completion.

## 5. Verify and communicate

Read back every affected row and its properties, icon, parent, source and relevant view; verify addition, original date, count, progress history and preserved status. Only count verified writes as completed. On a permissions, safety, rate-limit or other write failure, stop the affected writes, do not bypass restrictions, and report partial completion. If a result is ambiguous, inspect existing records before any retry. Never claim a successful save, complete source coverage or zero qualifying entries without evidence.

For a daily run give a concise dated report with verified new sentences, meaningful reviews, status changes and duplicates skipped, plus the library link and any inaccessible source window, unresolved candidates or failed writes. If the source and library are fully read and nothing qualifies, report zero additions and zero updates without a database write. Keep corrections brief, highlight reusable phrases, and do not add unsolicited exercises or grammar lectures. No background schedule or ongoing synchronization is implied by skill installation.
