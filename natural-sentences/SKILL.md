# Natural Sentences

Help the learner build a deliberate sentence collection and use its expressions independently. Keep sentence collection separate from Vocabulary, Speaking, Listening and Writing Memos, review-task scheduling and quizzes. A request for one does not authorize the others.

## Discover and scope

Find the learner's Natural Sentences page and its intended live Sentence Library through existing private configuration or exact-title search. Fetch the entire current framework including toggles, the database, current data-source schema, views and relevant entries before writing. Verify parentage and access; do not use similarly named dummy databases. Apply live rules and later explicit user instructions above these portable defaults. If source, rules, schema, or duplicate coverage is incomplete, do not guess or create a duplicate; explain the specific gap. Keep user IDs, personal examples, source sentences, private URLs and credentials out of this skill and any public repository.

## Select and save

- The default collection is learner-curated: collect sentences personally typed in the dedicated collection context. Do not automatically harvest other conversations, practice, memos or assistant suggestions. An explicit request to save a specific sentence in another context or an assistant-written sentence authorizes that specific item; distinguish its real authorship and source. A request to explain a sentence alone is not a request to save it.
- Follow the current daily cap (the existing framework sets at most ten new sentences per day), using the actual local learning date and checking existing additions. A request to save an existing entry is not a new entry. When count or date cannot be established, report the gap rather than exceeding the cap silently.
- Search exact wording and meaningful shared key phrases, including variants and nearby items, and inspect the relevant records. If the same sentence exists, link and update its relevant key phrases only when requested or clearly implied; retain all user content. For similar patterns follow the live deduplication rule while preserving both records and learner edits; do not delete or replace an existing record without explicit authorization. If uncertainty remains, surface candidates instead of inventing uniqueness.
- Preserve the original and intent; lightly correct or naturalize selected text, explain meaningful changes, and identify original and editorial wording. Do not present a generated example as the learner's independent production. Maintain any qualified or uncertain factual claims; linguistic polishing is not fact verification.
- Fetch schema and use its actual fields and options. For new entries use the complete natural sentence, meaningful native emoji icon, one main category, relevant optional tags, reusable key phrase(s), concise reason, actual added date, initial unreviewed status and zero review count if supported. Include source and an explicitly labelled illustrative personal example only when useful and supported; do not fabricate personal experiences or independent usage. Preserve existing fields, user notes, related pages, status and history.

## Practice and evidence

Use active recall, learner-created examples, correction and later transfer when requested. Capture original learner attempts and dates, distinguish prompted practice from independent natural use, and do not equate reading or explanation with performance. Only record a meaningful review that actually occurred; update the dated progress log, last-reviewed date and review count according to current rules, without overwriting history. Do not change learner-owned status without authorization or claim mastery from recognition or a single response. The current framework requires natural, correct use on at least three separate occasions for Mastered; even then preserve learner control and apply live rules. Do not invent prior reviews, dates or use.

## Verify and report

Read back created or changed rows, properties, icon, parent and the relevant view when applicable; confirm no duplicate, exact sentence, additions and preserved status and history. If a write is uncertain, inspect before retrying. Report the link, additions or existing match, and any incomplete step; never claim successful sync without verification. Do not change database schema, schedule reviews or create background automation unless requested.
